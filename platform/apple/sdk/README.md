# Mini Apple SDK (to build without a Mac)

Apple's SDK (Xcode) only installs on a Mac. To build the iPhone and Mac apps on Windows or Linux,
`platform/ios/build_ipa.sh` and `platform/macos/build_mac.sh` use this instead, with the clang and lld
of the Android NDK:

- `include/`: the few declarations of the frameworks used by `platform/ios` and `platform/macos`
  (the Objective-C runtime, `CGGeometry` and the bitmap images of Core Graphics, `CFData`, the output
  audio units of AudioToolbox, the display link of CoreVideo), at the same paths as the real headers.
  Also used by the test tool `tools/iosmock` (Windows).
- `libc/`: the functions of the C library the code uses (stdio, stdlib, string, math, unistd, mkdir,
  threads, clocks), declared as on Darwin (`stderr` is `__stderrp`, `errno` is `*__error()`, `mode_t`
  is 16 bits...). The basic headers (stdint, stddef, stdbool, stdarg, stdatomic, arm_neon) are those of
  the clang compiler.
- the system libraries (libSystem, libobjc, UIKit, AppKit, Metal...) are replaced at link time by
  `.tbd` files generated by the scripts: the list of the symbols the code uses, sorted by library. On
  the iPhone and the Mac, the real libraries are used.

On a Mac with Xcode, the scripts take the real SDK (`xcrun`) and use nothing from here: a compile
error there would point to a wrong declaration of this mini SDK.

No file of Apple is copied here: only declarations written for this project.
